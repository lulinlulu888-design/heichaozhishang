# 黑潮之上游戏管理后台

独立 Vue 3 + Vite + TypeScript + Element Plus 前端，采用 Pinia、Vue Router 与 API 层分离。只读参考 `D:/project/so-im/admin` 的技术选择和布局、路由、请求分层，没有复制其业务页、账号配置或运行脚本。

## 信息架构

| 分组 | 页面 | 当前实际能力 |
| --- | --- | --- |
| 运营管理 | 运营总览 | 真实玩家、战斗、可用关卡计数，服务状态、生效配置版本与运营开关 |
| 运营管理 | 玩家管理 | 创建本地玩家、编辑昵称、保存大厅偏好、读取已有战斗记录 |
| 运营管理 | 运营配置 | 完整五字段草稿、CAS 保存、版本化发布、历史版本回滚 |
| 运营管理 | 操作日志 | 服务端持久化的最近 100 条真实管理操作及结构化详情 |
| 游戏内容 | 角色目录 | 35 位原始角色目录，当前样本已有的英文名、头像路径及内容详情 |
| 游戏内容 | 卡牌目录 | 当前 catalog 提供的卡牌样本，原始消耗、等级、技能 ID、描述与资源路径 |
| 游戏内容 | 关卡目录 | 已启用场景、实际默认关卡、规则定义 ID、源战斗 ID、参战角色 |
| 开发工具 | 资源恢复 | 恢复进度、预览环境、原始动作和逆向证据；与运营主页分开 |

玩家与战斗数量来自本地数据库，不表示在线人数。卡牌样本不等于源 APK 全部卡库；未恢复的字段不编造。艾尔莎标记为当前客户端优先，与原版初始发放或所有权规则分开。角色、卡牌和关卡目前是只读内容目录，不提供虚构的创建、删除、掉落或平衡编辑按钮。

## 运营配置与写入

配置字段为 `serverName`、`motd`、`allowNewProfiles`、`allowNewBattles`、`defaultEncounterId`。已启用关卡时，默认关卡必须来自当前真实目录；没有关卡时才允许空选择。

保存草稿不立即改变服务行为。发布生成新的生效版本；回滚使用指定历史设置生成另一个新版本，不覆盖历史。草稿保存、发布与回滚使用 `expectedRevision`，发布与回滚另带幂等 `requestId`。发布或回滚成功后重新 GET 当前配置，防止历史请求回执被误显示为当前生效版本。

遇到版本冲突时重新读取最新服务版本，保留本次表单输入并显示错误，需再次点击保存。大厅网络重试复用相同内容的请求 ID。玩家昵称与大厅选择分别使用各自资料版本和大厅版本。写入成功后刷新真实操作日志；失败、初始化和已有历史不补造成管理日志。

运营开关由服务端强制执行。管理端根据生效配置禁用新玩家创建；已有玩家及战斗资料继续可读。保存大厅偏好不会自动切换当前运行的 UE 编辑器画面。

## 运行

```powershell
pnpm --filter @hczs/admin dev
pnpm --filter @hczs/admin typecheck
pnpm --filter @hczs/admin build
```

开发页仅监听 `127.0.0.1:7471`，将 `/api/admin/v1` 代理到 `127.0.0.1:7460`。改写 Host 以匹配后端回环校验，同时保留浏览器 Origin。生产预览由 `admin/serve.mjs` 提供 `dist` 静态文件与同源 API 代理，默认 `127.0.0.1:7470`，由项目独立 PM2 托管。

当前面向个人本地管理，没有多管理员账号、角色权限或公开部署。管理 API 与新游戏客户端 API、未知旧游戏协议分开。MongoDB 支持运营配置和审计；SQLite 仅历史迁移和回归使用。

## 文件分层

| 路径 | 职责 |
| --- | --- |
| `src/api` | 类型合同、HTTP 错误、管理接口 |
| `src/stores` | Pinia 数据获取与当前生效状态 |
| `src/router` | 运营、内容与开发工具路由 |
| `src/views` | 八个业务页面 |
| `src/utils/audit.ts` | 结构化审计摘要的显示映射 |
| `src/App.vue` | 分组侧栏、顶栏与全局状态 |
| `src/styles.css` | 自适应浅色样式 |

依赖锁在根工作区；允许安装脚本仅 `esbuild` 与 `vue-demi`。第三方 `@vueuse/core` 的 PURE 注释有 Rollup 提示，构建成功。后续真实运营能力规划见项目 `docs` 中管理后台规划；未实现功能不提前显示为可操作项。
